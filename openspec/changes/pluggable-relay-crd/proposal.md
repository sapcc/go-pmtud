## Why

The L3 support work (`eliminate-l2-dependency`, PR #69) replaced raw L2 Ethernet
frames with UDP unicast on port 4390 for relaying ICMP fragmentation-needed
packets between nodes. UDP is simple but adds a new network exposure: every node
must accept inbound UDP 4390 from every other node — a non-trivial requirement in
hardened environments with strict host firewalls or cloud security groups.

go-pmtud already holds an RBAC-governed API server connection for node discovery.
Routing the relay signal through a Kubernetes CRD reuses that connection and needs
zero new firewall rules. But UDP remains the right default where the API server is
distant or event volume is higher. Rather than replacing one with the other, the
relay transport should become a pluggable seam so operators pick the backend that
fits their topology, and future transports (message queue, etc.) can be added
without touching capture or injection code.

## What Changes

- Introduce a `Relay` interface (`internal/relay`) that abstracts the transport:
  `Send` on the capture side, `Start`/receive on the injection side. Packet
  capture (NFLOG) and packet injection (TUN `pmtud0`) become transport-agnostic
  shared code.
- Refactor the existing UDP path (PR #69) into a `Relay` implementation
  (`udp_linux.go`). Behavior is unchanged; it becomes one backend among peers.
- Add a CRD-based `Relay` implementation. Each node writes a namespaced
  `PMTUNodeRelay` object when it captures an ICMP 3/4 packet; all daemon pods
  watch the namespace, inject the payload via `pmtud0`, and the object is deleted.
  A GC loop reaps expired objects.
- Add a `--relay-backend=udp|crd` flag (default `udp`). One backend is active per
  process.
- Add Go API types (`api/v1alpha1`) for `PMTUNodeRelay`; the CRD manifest, RBAC,
  and deepcopy are generated by `controller-gen` (already wired via
  go-makefile-maker), not hand-written.
- Define a layered testing strategy: unit tests, local integration (network
  namespaces and/or Kind), and an automated E2E path.

## Capabilities

### New Capabilities
- `pluggable-relay`: Select the inter-node ICMP relay transport at runtime via a
  single backend interface. Ships with two backends — UDP unicast (existing) and a
  Kubernetes CRD relay that requires no new ports or firewall rules.

### Modified Capabilities
- `udp-replication`: The UDP sender and receiver are refactored to sit behind the
  `Relay` interface. Observable behavior (ports, packet format, loop prevention,
  source validation) is unchanged.

## Impact

- **Code**: New `internal/relay` package (interface + UDP backend + CRD backend +
  shared TUN injector). `internal/nflog` loses the UDP send loop, calls
  `relay.Send`. `internal/receiver` shrinks to the shared injector or is folded
  into `internal/relay`. New `api/v1alpha1` types. `internal/cmd` gains
  `--relay-backend` and wires the chosen backend.
- **APIs/Flags**: New `--relay-backend` (default `udp`), `--relay-namespace`
  (default from `POD_NAMESPACE`), `--relay-gc-interval` (default `60s`).
  `--replication-port` retained for the UDP backend.
- **CRD**: New `PMTUNodeRelay` (namespaced, `pmtud.cloud.sap/v1alpha1`), generated
  by controller-gen.
- **RBAC**: CRD backend needs `create/get/list/watch/delete` on `pmtunoderelays`
  in the daemon's namespace (namespaced `Role`, not `ClusterRole`).
- **Dependencies**: None new — controller-runtime, controller-gen already present.
- **Deployment**: Helm chart changes (install CRD, add RBAC, drop UDP port when
  using CRD backend) live in `sapcc/helm-charts` and are **out of scope** for this
  change — tracked as follow-up.
