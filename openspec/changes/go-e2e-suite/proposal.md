## Why

The Kind-based lab (`lab/`) validates go-pmtud PMTU replication across an L3
boundary, but its provisioning and test logic live in ~785 lines of bash across
12 scripts. This has become hard to maintain:

- **Fragile orchestration.** `set -euo pipefail` with `|| true` escape hatches
  hides failures; errors surface late and vaguely (e.g. the `test-e2e.sh`
  failure that was actually a missing `python3` in Kind nodes).
- **String-parsed cluster state.** Assertions grep `kubectl -o jsonpath` output
  and `ip -o addr | awk`, brittle against format drift.
- **Global-state hazards.** `kind create cluster` merges into `~/.kube/config`;
  a corrupted merge broke provisioning mid-run and required a manual reset.
- **No structured polling.** "Wait for convergence" is `sleep 5`, either flaky
  (too short) or slow (too long).
- **Two languages.** The daemon is Go with `client-go`/`controller-runtime`
  already in `go.mod`; the tests are bash. Contributors context-switch.

## What Changes

- Replace the bash provisioning + test scripts with a Go end-to-end suite built
  on **Ginkgo/Gomega**, driving the full lab lifecycle (provision → deploy →
  test → teardown) from one test binary.
- Provision **Kind clusters via the Kind Go API** (`sigs.k8s.io/kind`),
  eliminating the `~/.kube/config` merge-corruption failure class and giving
  programmatic, isolated kubeconfig handling.
- Keep genuinely shell-shaped docker plumbing (network create, `docker exec` of
  `ip`/`ethtool`/`tcpdump`/`curl`) behind thin typed `run()` / `dockerExec()`
  wrappers — **no** `docker/docker/client` SDK dependency.
- Assert cluster state through `client-go`/`controller-runtime` typed clients
  instead of `kubectl` string-grep.
- Replace every `sleep` with Gomega `Eventually`/`Consistently` polling.
- Test both `udp` and `crd` relay backends in a single `make e2e` run via an
  ordered backend matrix.
- Keep Kubernetes manifests and Kind/router configs as YAML (applied via
  `client-go` server-side apply); keep `observe.sh`/`status.sh` dev tools and the
  router `Dockerfile` as-is.
- Gate the suite behind a `//go:build e2e` tag so `go test ./...` (the
  `make check` path) stays green without docker/kind.

## Capabilities

### New Capabilities
- `go-e2e-lab`: A Go `lab` package that provisions and tears down the Kind lab
  topology (docker networks, Kind clusters, router, static routes, offload
  disabling) and deploys go-pmtud per relay backend.
- `go-e2e-validation`: A Ginkgo/Gomega suite asserting PMTU replication
  convergence and per-backend deployment configuration, replacing the bash test
  scripts.

### Modified Capabilities
- `kind-lab-setup`: provisioning moves from bash scripts to the Go `lab` package
  (topology and MTU semantics unchanged).
- `kind-lab-validation`: validation moves from bash scripts to Ginkgo specs
  (assertions unchanged in intent, stronger in mechanism).

## Impact

- **Code**: New `test/e2e/` (suite + specs) and `lab/` Go package. Deletes 11
  bash scripts (~700 lines). Keeps `lab/manifests/`, `lab/configs/`,
  `observe.sh`, `status.sh`.
- **Dependencies**: Adds `sigs.k8s.io/kind`, `github.com/onsi/ginkgo/v2`,
  `github.com/onsi/gomega` (test-scope). `client-go`/`controller-runtime` already
  present. No docker SDK.
- **Build/CI**: New `e2e` target in the hand-maintained `lab/Makefile`
  (`go test -tags e2e`). The autogenerated root `Makefile` is untouched; `make
  check` unaffected.
- **Developer workflow**: `make -C lab e2e` provisions, tests both backends, and
  tears down. `LAB_REUSE=1` skips provisioning; `LAB_KEEP=1` skips teardown for
  fast iteration.
