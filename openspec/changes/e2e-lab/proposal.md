## Why

Validating go-pmtud's PMTU replication (an ICMP fragmentation-needed captured on
one node must reach and update peer nodes) previously required real
infrastructure: adjusting MTU on core routers, SSHing into nodes, flushing route
caches. That is slow, manual, and unavailable in CI. go-pmtud needs a
**reproducible, automated e2e test** that a pipeline can run, plus a documented
procedure for the occasional check against a real cluster.

The behaviour under test is narrow. The daemon runs as a DaemonSet with
`hostNetwork: true` and `CAP_NET_RAW`; an init container installs a capture rule:

```
iptables -t raw -A PREROUTING -p icmp -m icmp --icmp-type 3/4 ! -i pmtud0 \
  -j NFLOG --nflog-group 33
```

so the chain is: a node **receives** an ICMP frag-needed on `PREROUTING` → the
NFLOG runnable (`internal/nflog`) relays it (UDP or CRD) → peers inject it into
their `pmtud0` TUN device → the peer kernel's route-cache PMTU updates. Proving
this needs two nodes and a way to make one **receive** a frag-needed — nothing
more. It does not need a router container, multiple clusters, custom docker
networks, an HTTP application, or a NodePort.

## What Changes

- Add a **single-cluster automated e2e** (`test/e2e/` + `lab/`), a Ginkgo/Gomega
  suite that provisions one Kind cluster (1 control-plane + 2 workers), deploys
  go-pmtud, exercises both `udp` and `crd` relay backends, asserts PMTU
  convergence on a non-originating peer, and tears down — all from one test
  binary gated behind a `//go:build e2e` tag so `make check` stays green without
  docker/kind.
- Provision Kind via the **Kind Go API** (`sigs.k8s.io/kind`) with an isolated
  temp kubeconfig (never merged into `~/.kube/config`), and assert cluster state
  through typed `controller-runtime` clients rather than `kubectl` string-grep.
- Generate a **real received frag-needed with a low-MTU forwarding hop**: the
  control-plane node enables forwarding and owns a `dummy` interface clamped to
  MTU 1280 with a directly-connected blackhole subnet; a worker sends a DF-set
  `ping` larger than 1280, so the hop returns a genuine ICMP frag-needed the
  worker's NFLOG rule captures. Because the MTU is set on an interface via
  netlink, it is honoured by the kernel directly — including on macOS Docker
  Desktop, where custom docker-network MTUs are not.
- Use **`ping -M do`** as the trigger. It self-bounds with `-c`/`-W` (cannot
  hang) and reports the frag-needed (`mtu = 1280`) as an explicit success signal.
- Replace every fixed `sleep` with Gomega `Eventually` polling.
- Provide a **manual runbook** (`lab/RUNBOOK-real-cluster.md`) for validating the
  same behaviour against a real ≥2-node cluster with a real MTU mismatch. This is
  deliberately not automated: a real cluster is not a pipeline target, so the
  automation value lives entirely in the single-cluster suite.

## Capabilities

### New Capabilities
- `e2e-lab`: a Go `lab` package (build-tagged) that provisions and tears down a
  single Kind cluster, configures the control-plane as a low-MTU forwarding hop,
  and deploys go-pmtud per relay backend.
- `e2e-validation`: a Ginkgo/Gomega suite asserting PMTU-replication convergence
  on non-originating peers and per-backend deployment configuration.
- `real-cluster-runbook`: a manual procedure for validating PMTU replication in a
  real multi-node Kubernetes cluster.

## Impact

- **Code**: New `test/e2e/` (suite + specs) and `lab/` package (Kind config,
  provisioning, hop setup, deploy, `ping` trigger, PMTU inspection).
  New `lab/RUNBOOK-real-cluster.md` and `lab/README.md`.
- **Dependencies** (test-scope): `sigs.k8s.io/kind`, `github.com/onsi/ginkgo/v2`,
  `github.com/onsi/gomega`. `client-go`/`controller-runtime` already present. No
  docker SDK — docker/`ip`/`ping` plumbing stays behind thin `run()` /
  `dockerExec()` wrappers.
- **Build/CI**: `make -C lab e2e` provisions → tests `udp`+`crd` → tears down
  (against one cluster). `LAB_REUSE=1` skips provisioning; `LAB_KEEP=1` skips
  teardown. Behind the `e2e` build tag, so `make check` / `go test ./...` are
  unaffected. The autogenerated root `Makefile` is untouched.
- **Supersedes**: this change consolidates and replaces the earlier
  `kind-cluster-lab` (bash two-cluster lab) and `go-e2e-suite` (Go port of the
  two-cluster lab) change proposals, neither of which reached `master`.
